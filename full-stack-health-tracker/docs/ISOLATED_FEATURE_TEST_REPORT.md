# Isolated feature test report — 2026-11-01

## Environment and scope
Tests used synthetic accounts and records, a disposable in-memory PGlite database initialized with the fixture and additive migrations, and headless Chromium against a local Next.js development server. PGlite serializes queries and is not a substitute for concurrency testing against PostgreSQL. The initial browser attempt encountered 500 responses because the temporary PGlite socket server allowed only one connection; raising the test harness connection limit resolved that harness issue. Both disposable services were stopped. No production database, push provider, deployment, or paid service was used.

## Results
- All 15 standalone verification scripts passed: activity, data export, grocery purchases, hydration engine, journals, plan archive and restore, planner, profile preservation, public shell, recipe upgrade, saved servings, sleep, water push, and weight progress. Some use mocks or PGlite and do not establish clinical validity or production delivery.
- Browser suites passed: installation (8 groups), core app (11 groups), budget/coach (6 groups), authentication (11 groups). The core and installation suites were rerun after asset changes.
- `scripts/verify-expanded-browser.cjs` passed: activity and sleep creation; food, exercise and measurement journal creation/edit, persistence and measurement deletion; recipe search/details/serving preview; grocery purchase persistence; water notification settings rendering; no uncaught page errors or missing image/font responses on those paths. This script creates a synthetic account: only run it against a disposable test server and database using `TEST_BASE_URL` and `ALLOW_SYNTHETIC_BROWSER_TEST=1` with Playwright Chromium installed.
- ESLint, Next type generation, TypeScript typecheck and production build passed. Build used a dummy database URL, not a live production database.

## Fixes
- A missing DM Sans font caused a 404. Added the Google Fonts variable font and its SIL Open Font License under `public/fonts`, and corrected the CSS reference. Source: https://github.com/google/fonts/tree/main/ofl/dmsans.
- Legacy built-in meal image paths and the wellness background pointed to missing files. Known legacy meal paths are resolved at display time to existing explicitly illustrative assets, preserving saved data; dashboard/auth backgrounds use an existing illustration. The existing fallback for other image errors remains. The expanded browser check watches for missing image/font responses on its exercised paths.
- Roll back these asset changes by reverting the relevant CSS, `illustrative-image.ts` and component references and removing the newly added font files. This restores the old missing-asset behavior; no database rollback is involved.

## Not established
Not every feature, browser, mobile OS, timezone, accessibility condition, concurrency pattern or deployment configuration was exhaustively tested. Real PostgreSQL concurrency, real device push delivery, actual permission-denial/device restrictions, external scheduler operation and OpenRouter/live external-provider behavior remain unverified. Web Push requires the documented configuration, migration 0006, scheduler and per-device permission; provider acceptance does not guarantee delivery. The personalized hydration estimator is a standalone draft, not connected to the app; personalized schedules and persistent Done/Snooze/Skip actions remain unfinished. Migration 0005 and 0006 have not been applied to production. `npm audit` could not run because there is no npm lockfile; earlier installation reported 22 audit findings, which are not a current completed audit. See `WATER_PUSH_SETUP.md` and `HYDRATION_METHODOLOGY.md` for limitations and setup.
